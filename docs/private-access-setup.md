# إعداد الوصول الخاص

أضيفت للمشروع بوابة دخول خادمية بكلمة مرور واحدة. كلمة المرور لا تُحفظ في GitHub ولا تُضمّن في JavaScript الذي يصل إلى المتصفح؛ يُحفظ فقط hash مملّح داخل متغير Server-only في Vercel، وتُصدر الجلسة في Cookie تحمل خصائص `HttpOnly` و`Secure` و`SameSite=Lax`.

## توليد قيمة كلمة المرور

من جهاز موثوق وبعد فك ضغط المشروع أو استنساخه، شغّل:

```bash
pnpm install --frozen-lockfile
pnpm hash-password
```

اكتب كلمة مرور من 8 أحرف أو أكثر. انسخ السطر الناتج فقط إلى متغير Vercel باسم `APP_PASSWORD_HASH`. لا تحفظ كلمة المرور أو الناتج في GitHub ولا ترسله داخل محادثة.

أنشئ متغيرًا ثانيًا باسم `SESSION_SECRET` وضع فيه سلسلة عشوائية طويلة. يجب ضبط المتغيرين في بيئة **Production** ويفضل ضبطهما أيضًا في Preview إذا كان مطلوبًا اختبار النسخ المعاينة.

## إعدادات Vercel

استخدم الإعدادات التالية عند ربط GitHub أو إنشاء المشروع:

| الإعداد | القيمة |
| --- | --- |
| Framework | Vite |
| Install Command | `pnpm install --frozen-lockfile` |
| Build Command | `pnpm build` |
| Output Directory | `dist` |
| Production Branch | `main` |

بعد حفظ المتغيرات، نفّذ **Redeploy** لآخر commit. افتح الرابط في نافذة خاصة؛ يجب أن تظهر شاشة الدخول قبل صفحات التطبيق. اختبر كلمة المرور الخاطئة والصحيحة، ثم اختبر زر تسجيل الخروج.

## حدود النسخة الحالية

بوابة الدخول تحمي الوصول إلى الواجهة العامة، لكن المهام والمواعيد والماليات ما زالت محفوظة داخل `localStorage` في متصفح المستخدم. لذلك لا توجد مزامنة تلقائية بين الأجهزة حتى يتم ربط قاعدة بيانات خاصة مثل Vercel Postgres أو Supabase. لا تضع بيانات شديدة الحساسية في نسخة الإنتاج قبل تفعيل قاعدة بيانات ومزامنة خادمية إذا كانت الحاجة تتطلب ذلك.

## فحوص الجودة

```bash
pnpm check
pnpm test
pnpm build
```

تشمل الاختبارات الحالية رفض كلمة المرور الخاطئة، قبول كلمة المرور الصحيحة، التحقق من Cookie الجلسة، وتسجيل الخروج.
